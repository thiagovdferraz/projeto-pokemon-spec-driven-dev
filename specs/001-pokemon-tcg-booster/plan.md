## Summary

Build a browser-based Pokémon TCG 151 booster pack opening game. A Python setup script
(`download_cards.py`) fetches all cards from the `sv3pt5` set via the `pokemontcg.io` API,
organizes images into 7 rarity folders under `assets/`, and generates `assets/index.json`.
The game is pure vanilla HTML/CSS/ES-module JavaScript — no framework, no bundler, no server
required at runtime. Players open packs of 6 unique cards revealed with CSS 3D flip animations,
following a two-slot probabilistic distribution (slot 5: 90/10; slot 6: 6-tier weighted draw).
The player's collection persists in `localStorage` and a progress panel tracks per-rarity completion.

## Technical Context

**Language/Version**:
- Game: Vanilla JavaScript (ES2022, ES modules), HTML5, CSS3
- Setup script: Python 3.9+

**Primary Dependencies**:
- Game: None (zero runtime dependencies — no framework, no library)
- Setup script: `requests` (Python, HTTP calls to `pokemontcg.io` API)

**Storage**:
- `localStorage` — collection persistence (`ptcg151_collection`, `ptcg151_meta`)
- `assets/index.json` — card manifest on disk (generated by setup script)
- `assets/<tier>/<card-id>.jpg` — card images on disk

**Testing**:
- Probabilistic distribution: seeded PRNG + assertion script runnable in browser console
- Collection persistence: manual open → reload → verify
- Responsiveness: browser DevTools device emulation at 320 px, 768 px, 1280 px

**Target Platform**: Modern browsers — Chrome 90+, Firefox 88+, Safari 14+, Edge 90+;
served via `python -m http.server` or any static host (or `file://` in Chrome/Firefox)

**Project Type**: Static web application (single HTML file + ES module JS files + CSS)

**Performance Goals**:
- All 6 cards revealed within 5 seconds (6 × 600 ms flip = 3.6 s sequence)
- Page load (after assets present): < 2 s on a local server
- `index.json` parse + pool build: < 100 ms for ~165 cards

**Constraints**:
- Zero server-side runtime — `file://` compatible (Chrome/Firefox) or static HTTP
- No external JS/CSS libraries (per constitution Development Constraints — each lib > 50 KB gzipped requires justification)
- `localStorage` ≤ 5 MB quota; collection JSON stays well under 50 KB
- Mulberry32 PRNG (~8 lines) is the only algorithmic dependency

**Scale/Scope**: Single player; ~165 cards in sv3pt5 set; single-page app; two views

### Source Code (repository root)

```text
download_cards.py           # Setup script: downloads cards, generates assets/index.json

assets/
├── index.json              # Card manifest (auto-generated)
├── 01_comum/               # Common card images
├── 02_incomum/             # Uncommon card images
├── 03_raras/               # Rare + Rare Holo
├── 04_duplo_raras/         # Double Rare etc.
├── 05_arte_secreta/        # Illustration Rare
├── 06_duplo_arte_secreta/  # Special Illustration Rare etc.
└── 07_legendaria/          # Hyper Rare

index.html                  # Single entry point — two <section> screens, no routing

css/
├── base.css                # CSS reset, custom properties (colors, spacing), typography
├── booster.css             # Pack-opening screen + card flip animation (perspective, rotateY)
└── collection.css          # Collection grid, filter tab bar, progress panel, copy badge

js/
├── config.js               # Distribution weights (SLOT_5_WEIGHTS, SLOT_6_WEIGHTS), rarity constants
├── prng.js                 # Mulberry32 seeded PRNG — exports mulberry32(seed) → () => float
├── card-pool.js            # Loads index.json, builds tier pools, exposes drawOne() / getPool()
├── pack-engine.js          # Assembles a 6-card pack using CardPool + PRNG; validates weights
├── collection-store.js     # localStorage read/write — load(), save(), addPack(), isAvailable()
├── booster-view.js         # Booster screen controller: button handler, flip sequence, DONE state
├── collection-view.js      # Collection screen: grid render, filter tabs, progress panel
└── main.js                 # App entry point: init CardPool, wire navigation, handle storage warning

docs/
└── assets.md               # Asset naming convention & folder map (constitution gate V)
```

**Structure Decision**: Single-project flat structure. No backend directory (pure front-end).
No `src/` wrapper — files live at root level for zero-config `file://` access. JS files use
ES module `import/export` without a bundler.
